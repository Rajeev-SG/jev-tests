# Test 1 — ad-platform corpus relevance sieve

**Verdict: NOT PROVEN.** On this corpus and this decision, Jev does not beat the
trivial "keep everything" baseline, and the ground truth itself is weak.

## What was tested

Real data: the public `Rajeev-SG/adpi-data` export of ad-platform-intelligence —
**837 real capability records** (Google Ads 304, Pinterest 212, TikTok 186,
Meta 135), generated by the live acquisition pipeline on 2026-09-17.

Decision: given a record, is it worth carrying into the expensive synthesis
layer, or is it a record the pipeline could not verify as a live, actionable
capability?

Ground truth: the pipeline's own outcome fields, held out of every classifier
input — `maturity == unknown` or `control_mode == not_applicable` means the
pipeline could not act on it. That labels **93 low-value / 744 worth (88.9%)**.

## Results (837 records)

| method | accuracy | drop precision | records dropped | worth records lost |
|---|---|---|---|---|
| always keep (baseline) | 0.889 | n/a | 0 | 0 |
| nav-word heuristic | 0.799 | 0.088 | 91 (10.9%) | 83 |
| **classifier.dev fast (Jev)** | **0.882** | **0.406** | **32 (3.8%)** | **19** |
| Jev + smart escalation (<0.7) | 0.871 | 0.347 | 49 (5.9%) | 32 |

- Jev's accuracy (0.882) is **below** the always-keep baseline (0.889). It is
  good at not losing useful records (2.6% false-negative rate) but it removes
  only 3.8% of the corpus, and 59% of what it removes is actually useful.
- Both tiers get worse once the outputs are combined: the smart tier's extra
  removals include more useful records than low-value ones.
- Confidence is not well calibrated for this task: at ≥0.95 auto-accuracy is
  0.961 on 54.5% coverage, but that "accuracy" is dominated by the 89% base
  rate, not by skill on the low-value records.

## The ground truth is the real problem

GLM-5.3-Flash independently judged 150 stratified records on the same question
(142 parsed): it agrees with the pipeline label only **52.1%** of the time
(106 of 142 said "worth"). A strong model does not reproduce this label, so the
label is measuring "the pipeline could not verify it", not "not worth
synthesising". Jev and GLM agree with each other 73.9% of the time.

## Cost and latency

| | value |
|---|---|
| records sieved | 837 in 1 batch |
| Jev batch latency | 5,123 ms (6.1 ms/record amortised) |
| Jev cost (measured) | $0.00 (classifier.dev free tier) |
| Jev cost (direct-API equivalent) | $0.0018 for the whole corpus at $0.042/1M input tokens |
| GLM-5.3-Flash sample cost (measured) | $0.0021 this run, $0.026 across all runs |
| GLM latency | p50 3,576 ms, p95 11,194 ms per call |
| illustrative GLM cost, full corpus | $0.110 unsieved vs $0.106 sieved — a 3.8% saving |

A 3.8% sieve saves 3.8% of downstream spend. At this corpus size that is
$0.004.

## What this does and does not prove

- Does prove: Jev can call the pipeline's own verification outcome from record
  text at 2.6% false-negative cost, far better than a keyword heuristic.
- Does **not** prove: that this saves money. The records it removes are ones
  the pipeline already flags, and it removes too few of them to matter.
- Blocker for a proper test: the raw harvested chunks are not public (raw HTML,
  snapshots and vendor prose stay in private storage per
  `ad-platform-intelligence/data/README.md`). A real pre-extraction sieve has to
  be measured on those documents, at the chunk level. This test measures the
  published *output* instead, and says so.

**Recommendation: do not put Jev in front of synthesis on this pipeline's
record stream today.** If a sieve is wanted, re-run this harness against the
raw cleaned documents from the corpus store, where both the input size and the
achievable removal rate are much larger.

## Reproduce

```sh
python3 tests/01_corpus_sieve/build_dataset.py     # pulls adpi-data, builds records.jsonl
python3 tests/01_corpus_sieve/run.py --glm-sample 150
```

Outputs: `raw.jsonl`, `summary.json`, `cost.json`, `decisions.csv`,
`calibration.csv`. Every third-party response is cached under
`results/.cache/`, so a re-run repeats the numbers without new spend.
